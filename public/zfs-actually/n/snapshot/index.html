Snapshots, backups, and actually sleeping at night 2/6 ← prev next →

The word "snapshot" sounds like a photograph—a captured duplicate of a moment, costing what the data costs. Actually, a ZFS snapshot copies nothing. Copy-on-write means the current state of a dataset is a tree of blocks that were never going to be overwritten anyway; a snapshot is just a named pointer to that tree, plus a promise: don't garbage-collect these blocks while I hold them. Creation is instant and free at any size.

The cost is deferred, not absent: it accrues later, as the live dataset diverges from the pinned past and the old blocks can't be freed.
