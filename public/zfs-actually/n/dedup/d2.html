Deduplication

concept
depth 1/3 − deeper + surface

The reasoning feels airtight: ZFS already checksums every block, so noticing duplicates should be nearly free—flip it on, especially with all these similar VMs. Actually, dedup requires the table of every written block's hash to be consulted on every write—which means held in RAM—and each entry costs "slightly more than 320 bytes of memory" (OpenZFS docs), forever, per unique block. When the table outgrows RAM, "each cache miss will require reading a random block from disk"—writes go random-read slow, which is the storage equivalent of walking with your shoelaces tied together.
